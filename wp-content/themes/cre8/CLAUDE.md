# CLAUDE.md

Guidance for Claude Code (and anyone else) working in this theme.

## Project overview

Custom WordPress theme for Cre8 Associates, built to match the Whistlefish prototype at cre8.whistlefish.co.uk (an ASP.NET site; a snapshot of its pages, CSS and images is in `~/Sites/cre8-reference`). It started from kestrels, itself based on the Origin starter theme by Marc Jenkins and uses Vite 8 for SCSS and JavaScript, with ACF Pro blocks for page content. Repository: `StuartChaffe/cre8`.

- The Git repository root is the WordPress install root. Only `wp-content/themes/cre8` is tracked; WordPress core, uploads and plugins are ignored.
- Required plugin: Advanced Custom Fields Pro. WP Migrate DB Pro is also installed.
- Run every command below from `wp-content/themes/cre8/`.

## Commands

```bash
npm install           # first time only (needs Node ^20.19.0 || >=22.12.0)
npm run watch         # build on change, BrowserSync live reload at localhost:3000
npm run development   # one-off build, unhashed filenames, source maps
npm run production    # minified build with content-hashed filenames
```

Local setup: copy `.env-sample` to `.env` and set `VITE_PROXY`, `VITE_HOST` and the SSL paths (omit the two SSL lines for plain HTTP). `.env` is git-ignored; never commit it.

## Compiled assets

`assets/` is build output and is git-ignored, so it never reaches a server through Git. GitHub Actions builds it and deploys the theme (see `README.md` > Deploying): for now it only runs by hand, because hosting is not decided yet. Edit `src/`, never `assets/`.

Each build starts by clearing `assets/css`, `assets/js`, `assets/fonts` and `assets/images`, so renamed or deleted source files do not linger. In `npm run watch` this happens once at start-up, so restart it after renaming files. Dev builds leave unhashed files and source maps. Deploys always run a fresh `npm run production`.

## Structure

```
src/js/scripts.js            entry point: navigation, reveal, hero-slider, trust-strip, project-form
src/js/editor.js             block editor script
src/styles/styles.scss       front-end styles
src/styles/editor-style.scss block editor styles
src/styles/base/             fonts, design tokens (:root custom properties), base, typography
src/styles/components/       buttons, sections, rich copy and facts, posts and search
src/styles/layout/           header, footer, page header, project form, Gravity Forms
lib/                         PHP modules, loaded by functions.php
blocks/                      ACF blocks, one folder each (block.json, template, scss, acf-json)
partials/                    header, footer, page header, post card
tpl-project.php              "Discuss a project" full-screen form (page template)
assets/                      compiled output (git-ignored)
```

Blocks: `hero-slider`, `trust-strip`, `page-header`, `card-grid` (lined or boxed), `sector-grid`, `product-cards` (feature or list), `about-split`, `split-media`, `content-block` (rich text plus facts panel), `cta-band`, `latest-posts`, `product-detail` (gallery, description and datasheet for one product page). `blocks/register.php` registers every folder that has a `block.json`. Their field groups were generated by a script with predictable keys (`field_cre8_<block>_<field>`); the importer relies on those keys, so keep them if you edit a group.

The design tokens are the CSS custom properties in `src/styles/base/_tokens.scss` (`--ink`, `--panel`, `--pink`, `--max` and so on). Use them rather than hard-coded colours. Inter is the only font.

Sections fade in on scroll when they have the `u-reveal` class. The CSS only hides them once `reveal.js` adds `has-reveal` to `<html>`, so nothing is hidden in the editor or without JavaScript.

### Menus

Four locations: `primary`, `footer` (Explore), `footer-connect` and `legal`. In the main menu a top-level item with children becomes a dropdown whose first link is "All <parent>", unless the parent's URL is `#`.

### Content import

The pages were imported once from the prototype with a one-off importer, since removed. It and the scripts that made the import data are in `~/Sites/cre8-reference/tools/`. The old `.aspx` addresses still redirect, through `lib/redirects.php` and the `cre8_redirects` option.

### Project enquiry form

"Discuss a project" is a Gravity Form (multi-page, with a percentage progress bar) defined in `lib/gravity-forms.php`. It is created automatically the first time an admin page loads with Gravity Forms active; its ID is in the `cre8_project_form_id` option. After that, edit it in Forms in WordPress. The definition only matters if the form is deleted.

- `tpl-project.php` (template "Project enquiry") is the full-screen page that shows it.
- Each step starts with an HTML field holding the step number, heading and intro. The first step's heading is the page's `<h1>`.
- Gravity Forms' own CSS is switched off; `src/styles/layout/_gravity-forms.scss` styles it. Choosing an answer on step 1 moves on (`src/js/components/project-form.js`).
- Notifications go to Theme Options > Enquiries (falling back to the admin email). `{cre8_phone}` is a merge tag for the Theme Options phone number.
- Spam protection is Gravity Forms' honeypot. Live sites need SMTP for the notification email.

## Conventions

- Function prefix `cre8_`, text domain `cre8`.
- Class names are BEM (https://css-tricks.com/bem-101/), following Stu's kestrels conventions:
  - Each ACF block is a BEM block named after its slug: `.card-grid`, `.card-grid__card`, `.card-grid--boxed`. Layout parts are blocks too: `.site-header`, `.primary-nav`, `.site-footer`, `.page-header`, `.search-form`.
  - Shared components: `.section` (`--panel`, `--light`), `.section-head`, `.container`, `.btn` (`--ghost`), `.text-link`, `.eyebrow`, `.lede`, `.lead`, `.text-mark`, `.rich-copy`, `.facts`, `.post-card`, `.post-grid`, `.breadcrumbs`, `.empty-state`.
  - States use `is-` (`is-active`, `is-open`, `is-scrolled`, `is-visible`); page-level states sit on `<html>`/`<body>` (`has-reveal`, `nav-open`, `js`). Utilities use `u-` (`u-reveal`, `u-highlight`); `.sr-only` stays as is.
  - Style elements by their class, not by tag (`.card-grid__title`, not `.card-grid h3`). Tag selectors are only for markup we don't write: rich text from the editor (inside `.rich-copy`, `__text` wrappers), WordPress pagination and Gravity Forms (`gform_*`, whose buttons `@extend .btn`).
  - Mixing a shared component onto an element is fine: `<p class="section-head__intro lede">`, `<a class="cta-band__btn btn">`.
- Indentation is tabs, with 4 spaces for JSON (see `.editorconfig`).
- Styles follow ITCSS order (settings, variables, utilities, base, layout, components, blocks). Block SCSS is picked up automatically by the `@import "../../blocks/*/*.scss"` glob in both `styles.scss` and `editor-style.scss`.
- Assets are enqueued through `vite_asset()` and `vite_asset_css()`, which read `assets/.vite/manifest.json`.
- New blocks: use the `/newblock` command. ACF field groups save into the block's own `acf-json/` folder.
- Escape output at the point of use: `esc_html`, `esc_attr`, `esc_url`, `wp_kses_post` for rich text.
- Fonts are self-hosted: Inter (variable, from Fontsource) lives in `src/fonts/` with its SIL Open Font Licence, is declared in `src/styles/base/_fonts.scss` and is copied to `assets/fonts/` by the build. Latin subset only. Upright Inter is preloaded in `lib/enqueue.php`.
- Commit `package-lock.json`: the deploy workflow uses `npm ci`, which needs it.
- Record notable changes in `CHANGELOG.md` (the `/changelog` command does this).

## Templates and layout

- Every template wraps its content in `<main id="content">`; the skip link in `header.php` points to `#content`.
- The header is fixed. Pages should start with a Page Header or Hero Slider block; if the first block is something else, `.main--blocks` adds top padding so it clears the header.
- Each page needs exactly one `<h1>`, which comes from the Page Header or Hero Slider block. `page.php` adds none of its own.
- Posts, the blog page, search and 404 use `partials/page-header.php` directly (the Page Header block uses it too).

## Theme Options

Field group `acf-json/group_cre8_theme_options.json`: telephone, email, address, footer text, header button, social links, enquiry email, alert banner, analytics code and the unsupported-browser notice.

## Known gaps

- The pink is the prototype's final value (`#ec1b69`). Its homepage stylesheet still used an earlier pink (`#ec168c`); check with the client which is right.
- Several images on the prototype are Unsplash stock photos, and the import downloads them. Replace them with the client's own photos before launch.
- The prototype's blog and product detail page (LIMSNT CSC) had no content to import. The Products page links to the Discuss a project form until a product page exists.
- `lib/roles.php` gives editors Gravity Forms capabilities, but Gravity Forms is not installed.
- SVG uploads are allowed for administrators without sanitising.
- `style.css` version and the changelog are updated by hand.
